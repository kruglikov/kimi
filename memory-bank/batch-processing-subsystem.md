# Batch Processing System (`src/original-src/web/htdocs/kimi_ET/kimibatch/`)

The batch system is a **completely separate subsystem** from the web application. Scripts in `src/original-src/web/htdocs/kimi_ET/kimibatch/` are standalone PHP files intended to be run via command line or cron jobs, not through the web server routing.

## Shared batch utilities
- `src/original-src/web/htdocs/kimi_ET/kimibatch/db.php` — standalone DB connection helper (does NOT use `src/original-src/web/htdocs/kimi_ET/libs/database.php`)
- `src/original-src/web/htdocs/kimi_ET/kimibatch/kimi_general.php` / `src/original-src/web/htdocs/kimi_ET/kimibatch/kimi_general_sql.php` — shared utility functions
- `src/original-src/web/htdocs/kimi_ET/kimibatch/kimibatchtree.php` — web-accessible browser/overview of available batch scripts
- `src/original-src/web/htdocs/kimi_ET/kimibatch/files/vendor/` — independent Composer setup (PHPMailer 6.x) used by batch scripts that send email

## Campaign batch scripts
Each client/campaign has a set of scripts following a numbered naming pattern:
- `{campaign}01_` — import telephony data / phone number optimization
- `{campaign}02_` — prepare data for Elsbeth (generate outbound CSV files)
- `{campaign}03_` — process Elsbeth output files (import call results)
- `{campaign}04_` — status updates (mark open tickets as "in progress")
- `{campaign}05_` — email data preparation
- `{campaign}check.php` — status/sanity check dashboard
- `{campaign}report.php` — reporting
- `{campaign}schnupd.php` — "Schnellupdate" (quick status update)
- `{campaign}exp.php` — export scripts
- `{campaign}imp.php` — import scripts

## Per-campaign data files (`src/original-src/web/htdocs/kimi_ET/kimibatch/files/{campaign_id}/`)
- `Scripts/` — SQL scripts for data maintenance, schema patches, one-off migrations
- `Services/` (campaign 43 only) — service definition text files
- `Templates/` (campaign 43 only) — email and SMS templates (`.html`, `.txt`)
- `IN/` — CSV files generated by batch scripts, consumed by Elsbeth
- `OUT/` — CSV files produced by Elsbeth, processed by batch scripts

## What the 2026-09-08 production delivery brought into `src-dev/`

On 2026-09-08 the hosting provider copied the current production document root onto the dev server, and that copy was recorded in the app repository `git@github.com:viktarkruhlikau/kimi.git` as commit `0a71298`. Measured against the previous content of the deployed tree `src-dev/original-src/web/htdocs/kimidev_ET/`, the delivery **added 77 PHP files under `kimibatch/`**, not counting the vendored PHPMailer copies.

Those 77 files are not all new work. **63 of them already exist** in the untouched reference tree `src/original-src/web/htdocs/kimi_ET/`, which is the archive the client delivered at the start of the engagement — they were simply missing from the older export the dev tree had been built from. **14 are genuinely newer than that archive**: the eleven COEO CH language-variant preparation scripts `coeochde02_tagl_daten_fuer_elsbeth_import_alleP1.php`, `coeochde02_tagl_daten_fuer_elsbeth_import_alleP2.php`, `coeochde02_tagl_daten_fuer_elsbeth_import_alleP3.php`, `coeochfr02_tagl_daten_fuer_elsbeth_import_alle.php`, `coeochfr02_tagl_daten_fuer_elsbeth_import_alleP1.php`, `coeochfr02_tagl_daten_fuer_elsbeth_import_alleP2.php`, `coeochfr02_tagl_daten_fuer_elsbeth_import_alleP3.php`, `coeochit02_tagl_daten_fuer_elsbeth_import_alle.php`, `coeochit02_tagl_daten_fuer_elsbeth_import_alleP1.php`, `coeochit02_tagl_daten_fuer_elsbeth_import_alleP2.php` and `coeochit02_tagl_daten_fuer_elsbeth_import_alleP3.php`, the two data-folder scripts `kimibatch/files/16/Scripts/oko04_mehrfach_tickets_anzeigen.php` and `kimibatch/files/27/Scripts/okoexp.php`, and the dated backup `kimibatch/okoimp_save_20260614.php`, whose name carries the date 14 June 2026 and is therefore direct evidence that the delivery is newer than the original archive.

Of those 77 files, **67 are still present** and **10 were removed afterwards**: the eight scripts of the client-approved removals described above, which the delivery had reinstated because production still carries them, plus the two web-reachable diagnostic pages `kimibatch/phpinfo.php` and `kimibatch/kimiphpinfo.php`, which expose the full PHP configuration to anyone who can reach the host and were deleted for that reason.

The COEO CH family means the campaign list above is operated per language: `coeochde` for German, `coeochfr` for French and `coeochit` for Italian, each with an `alle` script and the three partition scripts `P1`, `P2` and `P3`.
